# 段階2：Notion からの取り込み（計画）

Notion の「レシピ / 買ったもの / 読書記録」の過去データを、**一度だけ**記録アプリへ移す。
写真も Supabase Storage に移し直す。取り込み後は Notion を見に行かない（段階3の同期は別計画）。

## 方式：手元の Mac で動かす取り込み用プログラム（Notion API）
```
 Notion（3つのデータベース）
   │ ① Notion API で1ページずつ読む（写真の URL は1時間で切れるので、読んだらすぐ取りに行く）
   ▼
 Mac 上の取り込みプログラム  scripts/notion-import/
   │ ② 項目を変換（⭐→数値、選択肢、日付…）
   │ ③ 写真を縮小（アプリと同じ：1280px / スクショ1600px / 一覧用480px、向き補正）
   ▼
 Supabase（プロジェクトB）
   ④ 写真を kiroku-photos へ → ⑤ レコードを kiroku_records へ（notion_page_id 付き）
```
- **アプリ本体（画面）には手を入れない**。取り込みは別のプログラムで、公開サイトにも含まれない
- Supabase へは **ユーザー本人としてログイン**して書き込む（実行時にメールとパスワードを入力。保存しない）。
  → 管理者用の強い鍵（service role key）は使わない。いつもの「自分のデータしか触れない」ルールのまま
- Node 24 は TypeScript をそのまま動かせるので、ビルド不要

### 使う道具（開発用にだけ追加）
- `@notionhq/client`：Notion 公式の API ライブラリ
- `sharp`：Mac 上で写真を縮小する定番ライブラリ（アプリの canvas 縮小と同じ設定にそろえる）

### 秘密の値
`.env.import`（Git に入らない）に置く：
```
NOTION_TOKEN=ntn_...            # Notion のインテグレーションの鍵
NOTION_DB_RECIPES=...           # 各データベースの ID（URL の32桁）
NOTION_DB_GOODS=...
NOTION_DB_BOOKS=...
```
Supabase の URL と公開キーは既存の `.env` を読む。

## 進め方（3段階で安全に）
| コマンド | 何をするか | 書き込み |
|---|---|---|
| `npm run import:inspect` | Notion の項目名・種類・件数・写真の枚数と推定容量を表示。ページ本文に何が入っているかも数える | なし |
| `npm run import:dry` | 実際に変換して、数件の見本と「変換できなかった値」の一覧を出す | なし |
| `npm run import` | 本番の取り込み。途中で止まっても、もう一度実行すれば続きから | あり |

`inspect` の結果を見てから項目の対応表（下）を確定する。

## 項目の対応（仕様書より。inspect で確認して確定）
| アプリ | Notion | 変換 |
|---|---|---|
| レシピ：評価 | ⭐の数の選択肢 | ⭐の個数 → 数値 |
| レシピ：自分の料理画像 / レシピ写真 / 材料・作り方スクショ | ファイル項目 | 縮小して保存。スクショは1600px |
| 買ったもの：価格 | 数値 | そのまま |
| 読書記録：書名 | 「Title」項目 | タイトルへ |
| 読書記録：著者 | Notion のタイトル欄 | 著者へ |
| 読書記録：Duration・関数 | 数式 | 取り込まない（アプリで自動計算） |
| レシピ：「プロパティ」 | 未入力のテキスト | 取り込まない |
| 選択肢 | select / multi_select | Notion にあってアプリに無い選択肢は、コレクションの選択肢に追加 |
| 登録日 | ページの作成日時 | `created_at` に入れる（「登録が新しい順」が Notion の順番を引き継ぐ） |

## 二重登録・やり直しの防ぎ方
- 各レコードに `notion_page_id` を入れる（表の側で重複禁止になっている）
- 本番実行の最初に「取り込み済みの notion_page_id」を読み、済んだページは飛ばす → 何度実行しても増えない
- 写真のファイル名は「ページ ID ＋ 何枚目か」から決まる名前にする → やり直しても同じ場所に上書きされ、ゴミが残らない
- 1ページずつ「写真 → レコード」の順に保存。レコードが入ったページだけが「済み」になる

## 容量の確認（取り込み前にユーザーが実行）
Supabase の SQL Editor で、プロジェクトB全体の写真の使用量を見る：
```sql
select bucket_id, count(*) as files,
       pg_size_pretty(sum((metadata->>'size')::bigint)) as size
from storage.objects group by bucket_id;
```
目安：約350〜500件 × 写真の枚数 × 約230KB。`inspect` が推定容量を出すので、空き（無料枠1GB）と比べて判断する。

## ユーザーにお願いする作業
1. Notion で「インテグレーション」（アプリ連携用の鍵）を作る：https://www.notion.so/profile/integrations → 新規 → 種類「内部」→ 権限は「コンテンツを読み取る」だけ
2. 3つのデータベースそれぞれで「…」→「接続」→ 作ったインテグレーションを追加
3. 鍵と、3つのデータベースの URL を Claude に渡す（`.env.import` に書く）
4. 上の SQL で容量を確認

## 実装の手順
1. `scripts/notion-import/` を作る：Notion 読み取り / 変換 / 写真縮小 / Supabase 書き込みに分ける
2. `inspect` を作ってユーザーの Notion で実行 → 対応表を確定
3. `dry` で変換結果を一緒に確認
4. 本番取り込み → アプリで件数・写真・並び順を確認
5. `HANDOFF.md` 更新

## 気をつけること
- Notion API は1秒に約3回まで → 同時に動かすのは3ページまで、失敗したら待って再試行
- Notion の写真 URL は1時間で期限切れ → ページを読んだ直後にダウンロード
- 外部リンクの画像（Notion にアップロードせず URL を貼ったもの）は取りに行けないことがある → 失敗は一覧に出してスキップ
- HEIC など iPhone 形式の写真も sharp で読めるか、inspect の段階で確認
